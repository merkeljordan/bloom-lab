On your desk today

The chip on the Basys 3 is an AMD Artix-7 FPGA. Vivado, the program you will use to build and load your design, is AMD’s tool.

People at AMD start chips the same way you will start the flower: write down what it should do, choose the pieces, then describe them in RTL.

Artix-7 and Vivado came from Xilinx, which AMD acquired in 2022. Mention it if someone has seen the Xilinx name on the board or in older docs.

You are making a flower on a chip

Level 1

Two switches: water and sun. One LED. It lights only when both switches are on. Turn either switch off and the LED goes off.

Level 2

The same switches, but the flower grows in stages: seed, then sprout, then bloom. The circuit has to remember which stage it is in.

There is an optional window on the laptop later. It only shows the stage the board already picked.

The text you write is the circuit

A Python or C program runs on a computer that is already built. It follows your lines one after another.

Today the text is called RTL, for register-transfer level. It is a description of wires and memory, written in SystemVerilog. Many of those pieces exist at the same time.

The Basys 3 is a blank chip. Loading your design sets the chip up so it is that circuit.

Pause on RTL. It is the name for the text, not a kind of software.

We do these steps in order

  1. Write down what the flower should do.
  2. Choose the pieces: gates, and later a small memory.
  3. Describe those pieces in SystemVerilog.
  4. Simulate, and read the result.
  5. Load it onto the board and try the switches.

If simulation is wrong, change the description and simulate again. Then load that new design.

Step 2 is the microarchitecture. Use that word once they have seen a drawing, not before.

Vivado does three jobs

Simulate

Runs a test on your circuit in software. Pick the tb_ file and look for PASSED.

Build

Turns your description into a file the chip can load. Pick the top_level file and generate the bitstream.

Program

Sends that file over USB to the board. The green DONE light means it worked.

You do all three after every change. Every click is on your printout.

Show the Sources pane once on the projector: where the tb_ and top_level files are, and where Set as Top is. That is where most people get stuck.

Level 1

Bloom only when both are on

The flower blooms only when it has both water and sunlight.

Turn either switch off and the LED turns off immediately. This circuit does not remember anything.

This kind of circuit is called combinational. Say that word if the room has seen it. Otherwise "no memory" is enough.

So the circuit is one AND gate

flowchart LR W[water] --> G["AND gate"] S[sun] --> G G --> B[bloom]

This drawing is the microarchitecture: the pieces, chosen before the file. SW0 and SW1 are the inputs. LD0 is the output. There is no clock.

Ask what happens the moment sun turns off. The LED turns off immediately, because nothing is stored.

Write that gate down

Open flower_level1.sv. One line describes the AND gate. Leave out the clock.

module flower_level1 (
    input  logic water,
    input  logic sun,
    output logic bloom
);
    assign bloom = water & sun;
endmodule

Check it before the board

The test tries all four rows of the table. You want this message:

LEVEL1 TESTBENCH PASSED

If it fails, change flower_level1.sv and run the test again. Wait to load the board.

Then load the board

In Vivado, build top_level1. That name is the circuit Vivado programs onto the chip. Afterward, the DONE light on the Basys 3 turns on.

Try all four switch combinations. LD0 lights only when SW0 and SW1 are both on.

If the board and the test disagree, save the file, program the board again, and check the name is top_level1.

Level 1 could forget the switches the moment they changed. This one has to keep the stage.

A circuit with memory is called sequential. Introduce the word after the table, if you want the textbook name.

The memory is a register

A register is a few memory cells, called flip-flops, that hold a number until the clock tells them to take a new one.

This flower has three stages, so the number is 0, 1, or 2. That fits in two flip-flops.

StageNumberLED
Seed0LD0
Sprout1LD1
Bloom2LD2

One grow is a short pulse

The board clock ticks 100 million times a second. If the stage advanced on every tick while water and sun stayed on, the flower would finish before you could see it.

The project makes a signal called grow. It is 1 for a single clock tick, at the moment water and sun both become true. Pressing BTNU does the same thing while both switches are already on.

Your circuit should move forward only when grow is 1.

Draw this before you type

flowchart LR SEED -->|grow| SPROUT -->|grow| BLOOM

Bloom stays bloom. With no grow, seed and sprout stay put. Reset from any stage returns to seed. Sketch the arrows on paper before you open the file.

Three pieces, all there together

flowchart LR IN["grow + stage"] --> NS[Next-stage gates] NS --> REG["Register"] REG --> OUT[LED gates] OUT --> LED[LEDs]

Next stage

Gates. They look at grow and the number in the register.

Register

On the clock, it saves that next number. Reset saves 0.

LEDs

Gates. They light one LED from the saved number.

This drawing is the microarchitecture for Level 2. The file only describes it.

The next-stage gates and the LED gates are both working all the time. The clock is the moment the register saves a new number.

How the register is written

In flower_level2.sv the register looks like this. On reset it saves SEED. Otherwise it saves next_state.

always_ff @(posedge clk or posedge reset) begin
    if (reset) state <= SEED;
    else       state <= next_state;
end

The arrow <= is the register update. The other two blocks, next stage and LEDs, use = because they are gates.

Fill in the two gate blocks

Start the next-stage block with next_state = state, so a stage stays put unless you name a move. Include a default that returns to seed.

On the board

  1. Press BTNC. LD0 lights: seed.
  2. Turn water and sun both on. LD1 lights: sprout.
  3. Press BTNU. LD2 lights: bloom.

Another way to get the second grow: turn the switches off, then turn both on again.

A window can show the flower

The board also sends what it is doing over the USB cable: the stage, and whether water and sun are on. A small window on the laptop draws it, with rain, a sun, and the flower. The window only displays what the chip sends.

Open BloomViz.exe, pick the board's port, and press Connect.

Works with Level 1 and Level 2. Skip this if serial is not ready; the LEDs are enough. Without a board it opens in demo mode with on-screen switches. From the repo, python viz/bloom_viz.py does the same thing.

If something is wrong

  1. Vivado is red: read the first error.
  2. The test fails: name the input, then say what the description says should happen.
  3. The board disagrees with the test: save, program the board again, check top_level1 or top_level2, and on Level 2 press reset.
  4. It jumps straight to bloom: the stage is moving on every clock tick. Move only when grow is 1.
